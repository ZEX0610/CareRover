# 手表到小车集成契约（待手表实测通过）

## 现有小车不动的边界

当前主板为 ESP32-S3 主控，小车 AP 默认 `192.168.4.1`，CAM 为独立板；既有网页摇杆、人物跟踪、手势、MPU 和 OLED 保持原行为。本原型尚不改 `C:\CareRover\firmware\main_wireless` 或 CAM 源码。手表先作为 AP 的附加 STA，20 Hz UDP 发送至主板端口 45670。现有小车**尚不监听**此端口。测试时可用电脑串口读完整 JSON，无需切换电脑网络。

## `watch_v1` 报文

每包含 `type=watch_v1`、随机 `boot`、递增 `seq`、手表 `ms`、`cal`、`roll`、`vx/vy/wz`、`contact`、`hr/hr_valid/hr_held/hr_age`、`spo2/spo2_valid/spo2_held/spo2_age`、`sqi`。速度值为归一化**车身目标**：`vx>0` 前进、`vy>0` 右移、`wz>0` 顺时针。当前命令上限分别为 0.45/0.45/0.35；小车接收端可继续限幅。`*_valid=0` 时对应数值不可展示为真实测量；`*_held=1` 表示上次有效值，不是本帧新采样。`boot+seq` 供接收端去重和重启重同步；`ms` 不与小车时钟直接比较。

### 手势到速度（初稿，可按佩戴标定）

| 右臂动作 | 速度结果 | 处理 |
|---|---|---|
| 身体正前方水平举臂、静置约 0.8 秒 | 0 | 捕获中立俯仰角；BOOT 释放后重新归中。 |
| 肩关节向上/下 | `vx` 正/负 | 相对初始俯仰死区 7°，35° 达 0.45，指数平滑系数 0.25。 |
| 肩关节向右/左 | `vy` 正/负 | 由陀螺相对航向积分；死区 9°，40° 达 0.45，限制 ±65°，需周期性归中。 |
| 前臂/手腕横滚 | `wz` 正/负 | 局部 X 轴角速度进入阈值 35°/s、保持 18°/s、释放 100 ms；旋转优先，暂时把平移设为 0。方向须实物核对，可改 `WristMotion` 构造参数符号。 |

六轴 IMU 没有磁力计/外部基准，重力只约束俯仰和横滚；绕竖直轴的绝对朝向不可观测。因此左右肩转不可能同时具备“任何姿势均精确判向”和“永不漂移”；这里采用可归中的短时相对角。高动态加速度不用于更新姿态；最近一次 MPU 样本超过 180 ms 时目标归零。滤波不是凭空补齐失去的传感器信息。

## 到小车的实现顺序

1. 手表台架满足 `WIRING_AND_BENCH_PLAN.md`。确认电源不掉、温度可接受、PPG 真实表现，并在串口逐项确认左右/前后/旋转符号。
2. 主板增加独立 `WatchReceiver`：仅来自已连接 AP 客户端的 `watch_v1`，长度限制、字段范围/非有限数拒绝、`boot+seq` 去重、接收时钟维护 150–250 ms 指令租约，租约过期只把手表目标归零。主板使用自己收到包的时刻，不信任手表 `ms` 做超时。
3. 将手表动作作为新的显式 `WATCH` 模式的目标源，不覆盖 MANUAL/FOLLOW/GESTURE；切模式时清旧指令。网页摇杆在 MANUAL，人物跟踪在 FOLLOW，手表在 WATCH，各自授权显示清晰。网页急停、失联停、舵机控制周期、原有电源/姿态保护仍在小车层处理，但不要把单帧 IMU 抖动当成新制动条件。
4. 健康数据经主板统一状态通道给 OLED 和网页；标明来源 `watch`、更新时间、有效/保持/无数据。原车 MAX30102 若仍连接，需定义明确优先级，不能把两路 HR/SpO2 混成一对。建议手表接触且最近有效优先；否则回落原车读数，并在 UI 指示来源。
5. 先架空车轮、限速 0.2，逐一验收正负方向、超时零速、网页模式切换与急停，再落地低速。随后将限速放到实测允许值。检查摄像头视频/人物框/手势、原网页摇杆、OLED、健康显示均无回归。

## 预期 UI

网页在现有健康区标注 `Watch` / `Car sensor` 与实时/保持/无结果；运动区新增 `WATCH` 模式和“腕带在线、已归中、最近包年龄、当前 vx/vy/wz”。显示腕部 IMU 相对俯仰/航向与横滚动作状态，区分相对角与小车本体 MPU 姿态。OLED 行数有限，优先 HR/SpO2 数值与来源简写，运动状态用小图标/短字，不挤掉原动画和手势布局。上述均是**未来接收端实现要求**，当前网页/OLED 不会自动出现。
