# 远程通话、性能耦合与语音控制方案

## 通话系统边界

```text
车上 INMP441 → 主板 I²S RX → 20 ms PCM16 单声道帧 → 专用 WSS → 公网中继
公网中继 → 家长 HTTPS 网页（扬声器播放 / 按住说话 / 麦克风授权）
家长网页麦克风 → 专用 WSS → 主板播放队列 → I²S TX → MAX98357 → 8 Ω 扬声器

原通道不变：CAM MJPEG + @G/@P UART → 主板 → 原网页视频/人物/手势
原通道不变：原网页控制 WS → 主板现有模式/急停/超声波/舵机仲裁
原通道不变：HC-SR04 → AP+STA → Server酱
```

家长异地时无法直接访问小车 AP 的 `192.168.4.1`；设备须通过独立热点 STA 主动连接可公网到达的中继。iPad 可继续连接小车 AP 使用原控制页，但它若只有此 AP 网络、且 AP 不转发互联网，就**不能用同一连接打开公网通话页**；异地家长应使用有互联网的另一台设备。实验中继只允许一台设备/一位家长、分离令牌、证书校验、最大帧 648 B、缓冲和速率上限、不录音；实际服务上线仍需公网主机维护、端口/TLS/令牌轮换、访问日志脱敏与断网提示。当前实现是**演示原型**，不是无人值守商用通话服务。由于音频含儿童隐私，应清晰提示麦克风何时打开；独立固件需要串口输入 `remote` 才上传声音，未来整车需增加实体/网页可见的接通与挂断状态。

## 速度与资源预算

16 kHz×16 位×单声道约 **256 kbit/s/方向**，双向仅 PCM 载荷约 **512 kbit/s**（本实验帧 648 B×50 帧/s×2＝518.4 kbit/s，另加 WS/TLS/TCP/IP 开销）。浏览器和中继本机模拟通过，**尚未测实际 Wi-Fi 空口、TLS 堆、摄像头并发**。当前现场无音频基线：视频约 6.11 FPS、人脸约 1.31 FPS、手势约 3.06 FPS；Server酱 AP+STA 运行中主板最低空闲堆约 114 kB（见 `C:\CareRover\docs\windows-progress.md` 2026-09-25 项）。所以直接把常开双向 PCM+第二条 TLS 加入主板，确实可能降低视频/识别帧率或造成断连；**新电源不能消除这个瓶颈**。

建议将原型纳入整车时按以下顺序 A/B：

1. 原控制页与 CAM 不改，用专用音频任务、固定大小的 3 帧队列，满时丢**旧**音频，不阻塞摇杆、急停或图像；记录 20 ms 采集数、队列丢帧、WSS 重连、最小堆、RSSI、往返延时。
2. 先半双工“按住说话”：避免儿童端喇叭声音回灌单个 INMP441。对端未按说话时只听孩子。若要真正两边同时说话，优先考虑 ESP-SR AEC 的全双工低成本模式，但应按实际主板占用重新预算 PSRAM/内部堆和 CPU。[乐鑫 AEC 原文](https://docs.espressif.com/projects/esp-sr/en/latest/esp32s3/acoustic_echo_cancellation/README.html)
3. PCM+视频并发不达标时，可换低计算量 ADPCM（16 kHz、4 bit 约 64 kbit/s/方向）或在公网网关/家长端做 Opus，切勿把音频处理压到已在跑视觉推理的 CAM 核心上。压缩、丢包恢复和回声消除均需实测；当前原型没有宣称这些已完成。
4. 无损指标和准入目标分开：基线需记录无通话与通话中的 CAM HTTP FPS、实际浏览器帧数、人物/手势推理 FPS、网页命令 P95、主板最小堆、Server酱送达；作为首轮目标，可要求视频 ≥5 FPS、人物 ≥1 FPS、手势 ≥2.5 FPS、摇杆响应 P95 <200 ms、音频单向 P95 <300 ms、连续 10 分钟无重启。目标不是当前实测结果。

音频和视频的显示合成应在家长端/网页完成，不要让 ESP32 将音频重编码进 MJPEG。音频 WSS 与控制 WS 独立，分别限流与断线；通话断线只让音频静音，不改运动模式，不触发跟随状态变更。未来如果将家长远程控制也接入公网，需另行设计角色授权和急停优先级。

## “小爱同学/Siri”式语音控制

可行，但分两类：

- **有限中文命令（适合 Demo）**：如“停下、跟随我、取消跟随、向左、向右、前进、后退、原地旋转”。乐鑫 ESP-SR 提供 WakeNet、AFE 和 MultiNet，可在 ESP32-S3 离线识别自定义中文命令；MultiNet 输入为 16 kHz/16 bit 单声道。应先在独立音频原型/备用板测准确率、唤醒误触、噪声下响应、模型 PSRAM/内部堆与现有程序共存，再决定是否并入主板。[乐鑫 ESP-SR 入门](https://docs.espressif.com/projects/esp-sr/zh_CN/latest/esp32s3/getting_started/readme.html)、[MultiNet 命令词](https://docs.espressif.com/projects/esp-sr/zh_CN/latest/esp32s3/speech_command_recognition/README.html)、[模型资源基准](https://docs.espressif.com/projects/esp-sr/zh_CN/latest/esp32s3/benchmark/README.html)。
- **任意问答/自然对话**：单靠本车这颗 S3 + INMP441 不能等同 Siri；通常需要手机/公网服务上的流式 ASR、对话模型和 TTS，产生网络时延、隐私和可能的服务费用。也可以只把高层语义命令返回车上，机器人本地做动作授权。

将来识别到的动作应统一转换为现有 `set_mode` / `cmd_vel` 或内部受控动作请求，通过现有模式所有权、障碍物和急停仲裁执行；`stop` 可高优先级立即生效。**不要**从 ASR 回调直接调用四路舵机 PWM。连续“前进”应有明确持续/停止语义，ASR 单词结果不是持续运动指令；误识别动作要用短时窗口、方向确认或固定动作时长进行演示 A/B。网页摇杆、人物跟随、手势与语音之间需要一个可见的控制源优先级，不能同时给车轮发互相矛盾的命令。
